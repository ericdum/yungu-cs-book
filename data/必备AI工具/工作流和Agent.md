# 工作流和Agent

在这一章之前，我们是按照“在哪里使用AI”分类的：有的在网页里（Kimi、ChatGPT），有的在操作系统里（Copilot、豆包）。

但**Agent（智能体）** 不是一个新的“平台”，它代表的是一种**全新的使用范式**。

## 什么是Agent范式？

Agent的存在形式是多样的：它可以是一个网页插件，也可以是一个手机App，甚至可以深入到操作系统底层。**不论它身处什么层级，Agent的核心区别在于“思考方式”。**

- **传统工具（Tool）**：即使是拥有MCP的AI，也是**“被动响应”**  的。你让它“查询天气”，它查询完就结束了。它的每一次行动都需要人类的明确指令。
- **智能体（Agent）**：它是**“主动规划”**  的。当我们谈论Agent时，我们不再是把它当作一个简单的问答机器，而是把它当作一个**独立解决问题的个体**。

所以，Agent不是与“网页AI”或“系统AI”对立的概念。**当任何层级的AI开始拥有“感知-思考-行动”的自主闭环时，它就进化成了Agent。**

目前的Agent生态并不存在单一的进化路线，而是百花齐放。我们可以将它们大致分为三类，分别代表了不同的设计理念。

## 工作流

故事的一开始的问题源于大家发现大模型已经有了非常强的回答问题的能力，但是面对专业问题的时候，它会一本正经的胡说八道。比如，你问它“我们学校的食堂几点关门”，它可能会编一个时间给你。这时候，人们就想，能不能让大模型去“查一下资料”呢？

因此，Agent应运而生。它不仅能回答问题，还能主动去获取信息，解决问题。具体的方法是，先用大模型去分析问题，然后调用工具去获取信息，最后再用大模型去总结答案。这个过程可以重复进行，直到问题得到解决。

### 工具的进化：从代码到画布

最早的 Agent 技术之一是基于代码编排流程的工具：LangChain。它提供了一系列的工具，让开发者可以用Python代码来构建Agent。比如，它提供了一个“Chain（链）”的概念，让程序员可以用Python代码把“获取用户输入 -> 分析用户意图 -> 调用工具 -> 总结结果”这几个步骤串联起来。虽然灵活，但这依然要求使用者具备编程能力。

但是它的使用门槛太高了，于是就出现了Dify和扣子（Coze）这类“低代码/零代码”平台。它们把复杂的Python代码封装成了可视化界面上的一个个“节点”。你不再需要面对黑乎乎的终端，而是在一块无限大的画布上，通过拖拽和连线来设计AI的思考路径。这不仅降低了门槛，更重要的是它引入了**“工作流（Workflow）”** 的概念。

互联网上极具创意的人们，用这些平台开发出了各种各样的 Agent。比如心理咨询 Agent、占星师 Agent、AI 写作助手 Agent、AI 编程助手 Agent 等等。

他们的设计非常简单，就是把大模型和工具结合起来，形成一个流程，让它一步一步地去产出结果。从底层抽象来看，这类工作流本质上可以表示为一种 DAG（Directed Acyclic Graph，有向无环图）。

### DAG技术：定义思考的逻辑

为什么要用DAG来开发Agent？因为单纯靠提示词（Prompt）很难控制复杂的业务逻辑。

- **Prompt是线性的**：它像是在写作文，从头写到尾。一旦中间某个步骤出错，整个结果就会崩塌。
- **DAG是结构化的**：它像是在画流程图。你可以精确地控制AI“先做什么，后做什么，在什么情况下做什么”。

通过DAG，我们可以显性化地定义AI的思考逻辑，包括：

1. **条件分支（If-Else）**： 如果不使用DAG，你很难告诉AI：“如果用户问的是售后问题，请语气温柔并查询订单；如果用户问的是售前问题，请语气热情并推荐产品。” 但是在DAG中，你可以添加一个“分类器节点”，根据用户的意图，把流程引向完全不同的两条路径。
2. **错误重试（Loop）**： 即使是最好的模型也会犯错。在DAG里，你可以设置：“如果搜索不到结果，尝试换个关键词再搜一次”。这种自我修正的机制，大大提高了Agent的稳定性。
3. **并行处理（Parallel）**： 当你要写一份包含“市场分析”、“竞品对比”、“财务预测”的商业计划书时，DAG可以让三个AI节点同时开始工作，最后再汇总结果，效率提升三倍。

可以看出，DAG的本质，就是把人类专家的思维过程，翻译成机器能看懂的流程图。

### 知识库：注入专业的记忆

有了DAG，Agent学会了“怎么思考”，但它还需要“知识”来解决具体问题。这就引入了**RAG（Retrieval-Augmented Generation，检索增强生成）** 技术，也就是通俗说的**“知识库”**。

大模型虽然博学，但它有两个致命弱点：
1. **知识滞后**：它的训练数据可能只截止到去年。
2. **缺乏私有知识**：它不知道你们公司的《员工手册》，也不了解你的私人笔记。

RAG技术通过三个步骤解决了这个问题：

1. **切片与嵌入（Chunking & Embedding）**： 首先，你把你成百上千份的PDF文档上传到平台。系统不会直接把整本书塞给AI（那太贵也塞不下），而是会自动把文档切成一个个几百字的小片段。然后，利用**向量模型（Embedding Model）**  将这些文字片段转化成计算机能理解的数学向量存入数据库。
2. **检索与召回（Retrieval）**： 当用户提问时（例如：“出差餐补每天多少钱？”），系统会先在数据库里搜索与这个问题在这个向量空间里距离最近的片段。它可能会找到《员工手册》第15页关于“差旅标准”的那一段。
3. **增强与生成（Augmented Generation）**： 系统把找到的这段“参考资料”悄悄地贴在用户的提问后面，一起发给大模型。大模型看到的提示词其实变成了：“请根据以下参考资料回答用户问题：[...参考资料内容...]。用户问题：出差餐补每天多少钱？”

通过知识库，我们不需要重新训练模型，就能让一个通用的AI瞬间变成法律顾问、医疗专家或者企业内部的小百事通。

### 工作流的问题

但是，DAG 和 RAG 虽然强大，但它有一个不可回避的代价：**它高度依赖预先定义的流程。**

DAG 需要我们在设计阶段就明确规定每一步的执行逻辑。如果用户的问题稍微超出了既定流程，例如出现了意料之外的转折，系统就可能卡住，或者给出不理想的结果。这就好比你为一个机器人编写了一份详尽的说明书，但说明书中并没有写“如果下雨了怎么办”，机器人便只能在雨中停滞不前。

RAG 同样存在局限。它高度依赖切片策略与检索方式，既无法保证覆盖所有相关信息，也无法完全避免在切片过程中破坏原有语义结构。

相比之下，基于提示词的大模型 Agent 在面对开放式问题时表现出更强的灵活性，因为它不需要预先固化完整的执行流程。但这种灵活性，本质上是以牺牲可控性与可复现性为代价换来的。

因此，在云谷学校的教学实践中，出于对学生智能体思维方式培养的考虑，曾经使用过的“工作流 + RAG”教学模式在 2025 年被逐步淡化，取而代之的是以提示词为核心的 Agent 教学。

## 多角色协作

2025年7月，Cluade Code 上市，它为我们展示了基于提示词设计的多角色协作的潜力。

因为此前的AI编程软件使用单个 Agent 往往会力不从心。它一会儿要写代码，一会儿要测试，一会儿要写文档，很容易顾此失彼，出现“幻觉”。

于是，**Claude Code** 等前沿项目引入了**“多智能体协作（Multi-Agent Collaboration）”** 的范式。它允许我们定义多个 Agent，每个 Agent 都有自己的角色和职责。

这就像是开公司，我们不再强求一个人是全才，而是组建一个团队：

- **架构师Agent（Architect）**：它不写代码，只负责设计系统的整体结构和文件目录。它的Prompt被专门设计为关注宏观架构。
- **工程师Agent（Coder）**：它只负责接收架构师的指令，把具体的函数写出来。它专注于代码语法和逻辑。
- **测试员Agent（Tester）**：它负责运行代码，收集报错信息，并反馈给工程师。它专注于挑刺。
- **项目经理Agent（PM）**：它负责协调各方，确保项目按时推进。

并且你可以详细的规定每个角色的工作目标、工作方法和工作流程。例如，你可以规定架构师Agent在设计系统时，需要参考哪些文档，需要考虑哪些因素，需要输出什么格式的文档等等。同时它又不像DAG+RAG一样需要严格的流程定义，它允许Agent在工作过程中灵活调整。就好像你入职一家公司收到的员工行为手册和工作流程文档一样，它规定了你的工作目标、工作方法和工作流程，但它又允许你在工作过程中灵活调整。

这种**多角色的模式** 还带来了三个巨大的优势：
1. **专注度提升**：每个Agent的上下文（Context）更纯净，不容易被无关信息干扰。
2. **交互进化**：Agent之间的对话本身就是一种思维链的修正。架构师的设计可能会被工程师指出难以实现，这种“机机对话”能碰撞出更高质量的解决方案。
3. **提炼共享信息**：虽然上下文被切断了，但是Agent之间可以基于标准“文档沟通”，就像我们在工作中跨团队协作一样，将文档写好，其他人就知道怎么与你协作了。

这对于学校的人才培养来说也指明了一个新的方向：**设计程序** 还是**设计工作规范**？

## 通用自主智能体：第三种范式

如果说上面的“工作流”和“多智能体”还需要人类去通过DAG编排流程或定义角色，那么**Manus** 代表了AI的第三种范式：**通用自主智能体（General Autonomous Agent）**。

它不再仅仅是一个聊天框，也不是一个IDE里的辅助插件，而是一个拥有完整操作系统权限的 **“数字员工”**  。它虽然不是系统级AI，但是它在自己的虚拟机环境中运行，换句话说就是它拥有自己的电脑。它会用它自己的电脑帮你解决任何可以通过电脑来解决的问题，至少理论上是这样的。

当你对Manus说：“帮我做一份关于2025年新能源汽车市场的调研PPT。”

它不会给你生成一个大纲让你自己去填，而是会像一个真实的人一样行动：
1.  **自主规划**：它会自己分析任务，知道需要“搜索数据”、“阅读报告”、“提取观点”、“制作PPT”这几步。
2.  **使用工具**：它会控制你的鼠标和键盘，自己打开Chrome浏览器，在Google Scholar和咨询公司网站上搜索PDF。
3.  **信息处理**：它会下载几十份报告，快速阅读（远超人类速度），并提取关键数据存入Excel。
4.  **成果产出**：它会打开PowerPoint，根据提取的数据自动生成图表，填充内容，甚至调整排版。
5.  **自我反思**：如果打开某个网页失败了，它不会报错停止，而是会像人一样刷新页面或者换一个搜索源。

在这整个过程中，你处于 **“监督者（Supervisor）”**  而非 **“操作者（Operator）”**  的角色。你不需要懂DAG，也不需要配置知识库，除了下达指令和最终验收，中间的所有繁琐过程都由Agent自主完成。

这种从**Copilot（副驾驶）** 到**Autopilot（自动驾驶）** 的跨越，正是Agent技术目前最激动人心的进化方向。它预示着未来，每个人都将拥有一支由AI组成的“不知疲倦的专家团队”。
