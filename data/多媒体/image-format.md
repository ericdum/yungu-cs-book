# 认识数字图像

在学习如何处理图片之前，我们首先需要了解数字图像的本质。当你看到手机上一张精美的照片、电脑里的截图或者网页上的Logo时，它们在电脑内部究竟是如何被存储和表示的呢？

## 什么是像素？

在开始学习图片格式之前，我们先来认识一个最基本的概念——**像素**（Pixel）。

图像由无数个小点排列而成，这些点叫做像素。如果你把屏幕上的图片放大再放大，最终会看到一个个彩色的小方块——这就是像素。每个像素就像是一个微小的彩色瓷砖，无数个这样的瓷砖拼凑在一起，就形成了我们看到的完整图像。

这种由像素阵列组成的图像被称为**位图**（Bitmap），放大后会出现锯齿。

### 颜色是如何表示的？

在电脑的世界里，所有的颜色都是由数字组成的。最常用的颜色模型是**RGB模型** ——每个像素的颜色由三个数字表示：

- **R**（Red）：红色分量，取值0-255
- **G**（Green）：绿色分量，取值0-255
- **B**（Blue）：蓝色分量，取值0-255

例如：

- (255, 0, 0) = 纯红色
- (0, 255, 0) = 纯绿色
- (0, 0, 255) = 纯蓝色
- (255, 255, 255) = 白色
- (0, 0, 0) = 黑色

> **什么是灰度图像？**
>
> 当R=G=B时，像素就会呈现灰色。数值越大越亮（255,255,255 = 白色），数值越小越暗（0,0,0 = 黑色）。
>
> 灰度图像只需要记录一个亮度值，因此只需1个字节/像素，比彩色图（3字节/像素）小3倍。黑白照片、X光片等通常都是灰度图像。
>

## 一张图片有多大？

如果我们将每个像素的信息都完整记录下来，一张图片需要多大的存储空间？让我们来算一算：

**关键概念：**

- **分辨率**：横向像素 × 纵向像素，例如1920×1080表示宽1920像素、高1080像素
- **颜色深度**：每个像素通常需要3个字节（Red, Green, Blue各1字节）
- **Raw数据**：没有任何压缩的原始数据

**计算示例：**

一张1920×1080（全高清）的照片：

- 总像素数：$1920 \times 1080 = 2,073,600$ 像素（约200万像素）
- 原始数据大小：$2,073,600 \times 3 = 6,220,800$ 字节 $\approx$ 5.9 MB

一张4K照片（3840×2160）：

- 总像素数：$3840 \times 2160 = 8,294,400$ 像素（约800万像素）
- 原始数据大小：$8,294,400 \times 3 = 24,883,200$ 字节 $\approx$ 23.7 MB

你的手机拍摄的照片可能有4800万甚至更高的像素，原始数据将更加庞大！

## 为什么要压缩？

从上面的计算可以看出，一张普通照片的原始数据就有几十MB。如果不压缩，我们日常使用会遇到很多问题：

- **存储空间不足**：手机相册很快就满了
- **传输速度慢**：发送图片要等很久
- **网页加载慢**：一个网页可能需要几分钟才能显示完整
- **流量消耗大**：浏览图片会快速消耗你的手机流量

这就是为什么我们需要图片压缩技术——用更少的数据来表示同样的图像。

## 压缩的两种思路

压缩的核心问题是：**如何用更少的数据来表示同样的信息？**

根据"是否丢失信息"，压缩可以分为两大类：

### 无损压缩（Lossless Compression）

**原理**：找到数据中的规律，用更短的方式表达，完全不丢失任何信息。

**类比**：就像把"AAAAAABBBB"记录为"6A4B"，信息完整保留，但表达更短。

**特点**：

- 解压后可以100%还原原始图像
- 压缩率相对较低（通常只能减少50%-70%体积）
- 适合需要保留所有细节的场景

**典型格式**：PNG、GIF、BMP

### 有损压缩（Lossy Compression）

**原理**：丢弃人眼不容易察觉的细节，大幅减少数据量。

**类比**：就像画素描时省略一些细微的阴影变化，整体效果看起来差不多，但细节确实丢失了。

**特点**：

- 解压后无法完全还原原始图像
- 压缩率很高（可以减少90%以上体积）
- 适合照片等不需要像素级精确的场景
- 反复保存会导致质量逐渐下降

**典型格式**：JPEG、WebP（可选）

> **注意：避免反复保存JPEG**
>
> 每次保存JPEG文件，都会重新进行有损压缩，导致质量进一步下降。这就像复印的复印——每复印一次，清晰度就下降一点。
>
> 如果你需要多次编辑一张图片，建议保存为PNG或PSD等无损格式，只在最终导出时才转换为JPEG。
>

## 常见图片格式速查

了解了压缩原理后，让我们来认识一下常见的图片格式。**文件扩展名** 就是格式的标志，看到扩展名就能知道这张图的特性。

| **格式**  | **扩展名**  | **压缩类型**  | **透明**  | **动画**  | **最适合**  |
| --- | --- | --- | --- | --- | --- |
| JPEG | .jpg | 有损 | ✗ | ✗ | 照片、复杂色彩图像 |
| PNG | .png | 无损 | ✓ | ✗ | 截图、Logo、透明背景 |
| GIF | .gif | 无损 | ✓ | ✓ | 简单动画、表情包 |
| WebP | .webp | 可选 | ✓ | ✓ | 网页图片（新一代） |
| AVIF | .avif | 可选 | ✓ | ✓ | 网页图片（最新一代） |
| HEIC | .heic | 有损 | ✗ | ✗ | iPhone照片默认格式 |
| SVG | .svg | 矢量 | ✓ | ✗ | Logo、图标、插画 |

**各格式详解：**

- **JPEG**：最常见的照片格式，体积小但放大会有色块（马赛克）
- **PNG**：色彩完整，支持透明背景，体积较大
- **GIF**：最多只能显示256种颜色，不适合照片，但支持动画
- **WebP**：Google开发的新格式，比JPEG/PNG更小，兼容性在提升
- **AVIF**：比WebP更小的最新格式，但兼容性还在提升中
- **HEIC**：苹果设备的默认照片格式，压缩效率高但Windows兼容性差
- **SVG**：矢量格式，无限放大不失真，是Logo和图标的最佳选择

## 如何选择格式？

合理选择图片格式，能让你的文档既美观又轻便。以下是一个简单的决策指南：

> **图片格式选择流程**
>
> **问题1：这张图是什么类型？**
>
> - 真实世界拍摄的照片 → 进入问题2
> - Logo/图标/插画等图形 → 进入问题3
> - 动画/表情包 → 进入问题4
>
>
> **问题2：对照片质量要求高吗？**
>
> - 普通质量即可（分享、发朋友圈）→ **JPEG / WebP**

>
> **问题3：图形需要无限放大吗？**
>
> - 需要（Logo、图标、插画）→ **SVG**

>
> **问题4：动画复杂程度？**
>
> - 简单循环（表情包、loading动画）→ **GIF / WebP**

>

> **快速选择记忆口诀**
>
>
> - 照片发朋友圈 → JPEG
> - 截图要清晰 → PNG
> - Logo要放大 → SVG
> - 表情包动起来 → GIF
> - 网站要轻快 → WebP
>
>
